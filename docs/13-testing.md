# 13 测试与验收

## 1. 分层

| 层 | 运行环境 | 覆盖 | 何时运行 |
| --- | --- | --- | --- |
| 单元测试 | Linux / macOS | 各模块的纯逻辑：解析、匹配、编解码、密码学、状态机 | 每次 push |
| 属性与模糊测试 | Linux / macOS | 解析器、DNS 报文、协议解码器、规则引擎一致性 | 每次 push（固定种子短时）、每日（长时） |
| 引擎集成测试 | Linux / macOS | 进程内启动引擎：入站 → 路由 → 出站 → 本地测试服务器 | 每次 push |
| 互通测试 | Linux + Docker | 与第三方服务端实现的协议互通 | 每日、手动、涉及协议代码的 push |
| Apple 专有模块测试 | macOS | `AetherScript`、证书与 Security 框架交互 | 每次 push（`ios.yml`） |
| 构建验证 | macOS | iOS 工程完整构建 | 每次 push |
| 真机验收 | iPhone / iPad | 平台行为、内存、性能、系统集成 | 每个里程碑结束前 |

## 2. 单元测试约定

- 使用 Swift Testing（`import Testing`、`@Test`、`#expect`）；参数化测试用于表驱动用例。
- 测试数据放在 `Packages/AetherKit/Tests/Fixtures/`：`profiles/`、`modules/`、`rulesets/`、`dns/`（报文二进制）、`vectors/`（密码学与协议测试向量，注明来源）、`certs/`、`scripts/`。测试通过 `AetherTestSupport` 中的 `Fixtures.url(_:)` / `Fixtures.data(_:)` 按源码路径读取这些文件，不使用 SwiftPM 资源包。
- 黄金文件测试：解析结果摘要、诊断列表、渲染输出与 fixtures 中的 `.expected` 文件比对；更新黄金文件需要在提交说明中写明原因。以环境变量 `AETHER_UPDATE_GOLDEN=1` 运行测试会重写期望文件，重写后必须逐个人工检查差异。
- 覆盖率目标：`AetherProfile`、`AetherRules`、`AetherDNS` 的行覆盖率 ≥ 85%；`AetherOutbound` 的编解码与密码学部分 ≥ 85%；其余模块 ≥ 60%。CI 输出覆盖率报告，不作为硬性门槛，但下降超过 2 个百分点时在提交说明中写明。
- 时间与随机数通过注入的 `Clock` 与 `RandomNumberGenerator` 控制，测试不得依赖真实时间流逝（超时测试用可控时钟）。
- 测试不得访问公网；需要网络的测试只连本地进程或 Docker 服务。

## 3. 互通测试

### 3.1 服务端

`Scripts/interop/docker-compose.yml` 定义（镜像固定版本号，仅在 CI 中使用，不随产品分发）：

| 服务 | 用途 |
| --- | --- |
| shadowsocks-rust（`ssserver`） | SS AEAD 三种方法、SS 2022（AES 变体），TCP 与 UDP；simple-obfs 插件 |
| Xray-core | VMess（TCP、WS、WS+TLS）、VLESS（TLS、WS+TLS）、Trojan（TLS、WS+TLS）、SOCKS5（含 UDP）、HTTP 代理 |
| nginx | HTTP / HTTPS 源站：固定内容、大文件、gzip、分块、慢速响应、WebSocket 回显 |
| UDP 回显服务 | UDP 转发验证 |
| 测试 DNS 服务（如 CoreDNS） | UDP / TCP DNS、DoT、DoH 上游 |

证书由 `Scripts/interop/gen-certs.sh` 生成测试 CA 与服务端证书，测试中把该 CA 作为信任根。

### 3.2 用例

每个协议 × 每种传输组合：

1. 经该节点 `GET` 小文件，内容一致；
2. 下载 64 MiB 文件，校验 SHA-256，记录吞吐；
3. 50 个并发连接；
4. 服务端中途断开，客户端得到正确错误码；
5. 错误凭据 → `NET-031` / `NET-032`；
6. UDP（支持时）：DNS 查询与 1,000 个回显包，丢包率与顺序记录；
7. 测速请求（`generate_204` 由 nginx 模拟）结果合理。

结果写入 CI 摘要表格；某组合连续两次失败即视为回归。

## 4. 引擎集成测试

在进程内启动引擎（NIOPosix），不依赖 TUN：

- SOCKS5 / HTTP 代理入站 → DIRECT → 本地 HTTP 服务；
- 规则路由：同一组请求在不同规则下分别走 DIRECT、REJECT 系列、本地 SOCKS5 上游；
- Fake IP：向引擎 DNS 查询得到 Fake IP，再以该 IP 发起 SOCKS5 连接，验证主机名恢复与路由；
- 拒绝策略行为（关闭、DROP 保持、TINYGIF 响应、自动升级保护）；
- 策略组：模拟节点延迟与失败，验证 url-test 容差、fallback 顺序、load-balance 持久性、被动降级；
- 运行配置热替换：替换期间已有连接不中断，新连接使用新配置；
- MitM：测试 CA + 本地 HTTPS 源站，验证管线顺序与 Body 处理；
- 资源上限：超出并发上限的新连接被拒绝，背压生效（慢速消费者下内存不增长）。

`aether-cli run <配置> [--socks 127.0.0.1:1080] [--http 127.0.0.1:8080] [--module <模块>]` 可在开发机上手动运行同一套引擎（SOCKS5 入站不要求认证；系统 DNS 取自 `/etc/resolv.conf`；本地规则集相对配置文件所在目录读取，远程资源不下载），Ctrl-C 停止。

## 5. 性能与内存

### 5.1 基准（持续跟踪）

在 macOS 与 Linux 上以 Release 构建运行，结果写入 CI 摘要，与 `main` 上的基线比较，退化 > 20% 时警告：

- 规则匹配（[05 §5](05-rule-engine.md#5-性能目标) 的场景）；
- DNS 报文编解码；
- AEAD 分块加解密吞吐（各方法）；
- 配置解析（1 万行）。

实现为可执行目标 `aether-bench`（`swift run -c release aether-bench [--baseline 上次.json] [--output 本次.json] [--quick]`），数据由固定种子生成，不读网络。`core.yml` 的 `bench` 作业以 Release 构建运行，把 Markdown 表格写入 CI 摘要，并与 actions 缓存中上一次运行的结果比较；退化超过 20% 时输出警告（不使 CI 失败，GitHub runner 的性能本身有波动）。DNS 报文编解码已加入（M2-02）；AEAD 吞吐在 M3 实现协议时加入。本地运行前应清理 Release 构建目录（`rm -rf .build/*/release`）：增量 Release 构建在跨模块结构布局变化后可能得到损坏的二进制。

### 5.2 真机测量

每个里程碑结束前在真机上记录（Release 构建）：

| 场景 | 记录 |
| --- | --- |
| 空闲（已连接、无流量） | footprint |
| 浏览网页 5 分钟 | footprint 峰值、CPU |
| 200 / 500 / 1000 并发 TCP | footprint、hev 占用估算 |
| 单连接下载 | 吞吐（DIRECT、SS、Trojan、VMess），与不开隧道时对比 |

| 脚本密集（每个请求一个 http-response 脚本） | footprint、延迟增量 |

footprint 通过诊断页（`getMemoryInfo`）读取；数据追加到本文件末尾的"测量记录"表。

### 6.1 验收步骤

每个里程碑结束时，把该里程碑的验收行写成可照做的步骤与预期结果。安装包取自该版本 tag 的 GitHub Release 或 `release.yml` 的 artifact，按 [03 §8.4](03-project-setup.md#84-自行签名) 重签后安装。

#### V01 首次安装 VPN 配置；拒绝授权后再次授权（M0，v0.1.0）

前置：设备上没有 Aether 的 VPN 配置（设置 → 通用 → VPN 与设备管理 → VPN 中没有 "Aether"；有则先删除）。

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 1 | 安装并打开 App | 首页显示「未安装 VPN 配置」，开关可点；不出现「App Group 不可用」或「运行环境无效」错误页（若出现，记录页面上的错误码，按 03 §8.4 核对描述文件中的 App Group 与 entitlements） |
| 2 | 点开关 | 系统弹出「"Aether" 想要添加 VPN 配置」 |
| 3 | 点「不允许」 | 首页显示错误说明（无法保存 VPN 配置……）与「重新安装 VPN 配置」按钮；App 不崩溃 |
| 4 | 点「重新安装 VPN 配置」，在系统弹窗中点「允许」并验证密码 / 面容 | 首页变为「未连接」；设置 → VPN 中出现 "Aether" |
| 5 | 点开关 | 状态经「连接中…」变为「已连接」，开始计时；状态栏出现 VPN 图标；「隧道 → 状态」显示 `running`（每秒刷新） |
| 6 | 保持连接，用 Safari 打开几个常用网站、使用其它联网 App 1 分钟 | 正常上网，速度与不开 VPN 时无明显差别（空隧道只接管 198.18.0.0/15，不改 DNS） |
| 7 | 点开关断开 | 状态变为「未连接」，VPN 图标消失，无错误提示 |
| 8 | 在系统设置的 VPN 页面直接打开 / 关闭 "Aether" | 回到 App 后首页状态与系统一致 |
| 9 | 在设置中删除 "Aether" VPN 配置后回到 App | 首页显示「未安装 VPN 配置」；再次点开关可重新走第 2 步的授权 |
| 10 | 可选：打开「控制台」App 连接设备，筛选 subsystem 为主 App 的 Bundle ID | 能看到 `Tunnel starting`、`Tunnel running` 等日志；若有 `Keychain access group prefix differs` 警告，记录其中的 configured / resolved 值 |

记录：设备型号、iOS 版本、日期、每步结果（失败时附截图或错误码）。
